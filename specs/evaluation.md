# Evaluation of Cardinal from the session transcripts

## Intent

`cardinal run session-metrics` turns the Claude Code transcripts of every project into one row of
numbers per session (cost, user interventions, and what may explain a difference: Cardinal revision, model, Claude
Code version, project, issue), so the other evaluation tools compare sessions without reading the transcripts. It
measures; it does not judge.

## Requirements

- **EVA-1** (deterministic) `session-metrics [projects_dir]` must print a header line then one tab-separated row per session (one `<session>.jsonl` of a project directory, default EVA-15), with the columns `session`, `project`, `issues`, `revision`, `models`, `versions`, `start`, `duration_s`, `turns`, `tool_calls`, `input_tokens`, `output_tokens`, `thinking_tokens`, `cache_read_tokens`, `cache_creation_tokens`, `main_context_peak`, `advisor_models`, `advisor_calls`, `advisor_input_tokens`, `advisor_output_tokens`, `hook_refusals`, `skills`, `validations`, `other_messages`, `unreadable_lines`, `unknown_lines`, `missing_fields`.
- **EVA-2** (deterministic) An assistant message must be counted once per `message.id`, whatever the number of lines that repeat it: one turn, its `message.usage` tokens added once (`thinking_tokens` from `output_tokens_details.thinking_tokens`, 0 when absent), its model counted once; `tool_calls` counts the `tool_use` blocks of all its lines.
- **EVA-3** (deterministic) The transcripts of a session's sub-agents (`<session>/subagents/*.jsonl`) must be added to that session's row (turns, tool calls, tokens, hook refusals, skills, skipped lines), and must not produce a row of their own nor add typed messages.
- **EVA-4** (deterministic) A typed message (the same filter as `audit-sources`: a `user` line, not meta, not sidechain, not a tool result nor injected text) must count in `validations` when, trimmed, lower-cased and stripped of trailing `.` and `!`, it is one of `ok`, `okay`, `yes`, `y`, `oui`, `go`, `continue`, `lgtm`, `vas-y` or `c'est bon`, or answers the questions of a stop (only comma-separated items of a number then one letter from `a` to `h`, such as `1 a, 2 c`: two items at least, or one with a space, so `4k` is not one); any other typed message counts in `other_messages`.
- **EVA-5** (deterministic) A tool result with `is_error` whose text starts with `PreToolUse:<tool> hook error:` (`<tool>` with no space) must count one refusal for the hook named by the tool of the first `cardinal run <tool>` or `harness run <tool>` (before the rename) its text cites, under the name of the script it was (its `-` written `_`, `review-gate` named `require_code_review`), else by the stem of the first `.rs` file name it cites (`.rs` ending the name, so `.rsync` or `.rst` is not one) (`unknown` when none); `hook_refusals` lists `name=count` pairs joined by `;`, sorted by name. `skills` lists the `Skill` tool calls the same way, by `input.skill`.
- **EVA-6** (deterministic) `models` and `versions` must list the distinct `message.model` and `version` values of the session joined by `,`, in order of first appearance; `issues` the distinct `gitBranch` values other than `main`, `master` and `HEAD`, the same way (empty when none: a session is not forced onto an issue); `start` is the earliest `timestamp` and `duration_s` the whole seconds to the latest.
- **EVA-7** (deterministic) `project` must be the name of the directory holding the git common directory of the first `cwd` of the session (so a linked worktree counts with its main repository), the work tree of a submodule or of a separate git directory being its own project. When the `cwd` no longer exists and is under `<repo>/.claude/worktrees/` of an existing repository `<repo>` (a removed issue or agent worktree, ADR 0008), or it or a missing ancestor of it is named `<repo>-<x>` next to a directory `<repo>` that is the top level of a git work tree, whatever `<x>` (a removed worktree of ADR 0003 or ADR 0023, named after its branch or not; the `<repo>` whose `<x>` is a `gitBranch` of the session first, else the longest; a removed clone so named is then misattributed, which nothing left on disk can tell apart), that repository is the project; otherwise the last component of that `cwd`.
- **EVA-8** (deterministic) `revision` must be the `rev` value of the `.claude/cardinal.toml` (else `.claude/harness.toml`, for a commit before the rename of ADR 0015) committed on the default branch of the project at the session's `start` (the last commit of its first-parent history touching either file at or before it, so a commit merged later from another branch does not count); `self:<commit>` when that file names `source = "."` with no `rev` (the harness repository itself: the last commit touching `files/` at or before `start`); `unpinned` when the file exists then with no `rev`; empty when the project, the file or the history cannot be read.
- **EVA-9** (deterministic) A line that is not valid JSON must count in `unreadable_lines`, a line whose `type` is not in the known list of the script in `unknown_lines`, and an assistant line with no `message.id` or no `message.usage`, or a line of the conversation (`user`, `assistant`, `attachment`, `system`) with no `timestamp`, in `missing_fields` (the metadata lines, such as `ai-title`, carry none); none of them must stop the script or change the other columns.
- **EVA-10** (deterministic) The output must hold no text of a message, of a tool input or of a tool result: only identifiers, names, counts and timestamps.
- **EVA-11** (deterministic) With `--archive <file>`, the script must also merge its rows into that file: a session already archived is replaced by its new row, a session absent from the transcripts is kept, and the file stays one header then rows sorted by `start`; the parent directory is created when missing. An archive whose header is not the script's must be left unchanged, with an error and a non-zero exit, since its columns would not line up.
- **EVA-12** (deterministic) `audit-sources` and `session-metrics` must read the transcripts through the same module (`transcripts.rs` of the tools of the `cardinal` crate): the typed-message filter and the listing of projects and sessions are written once.
- **EVA-13** (deterministic) withdrawn: the readers are modules of `harness` (ADR 0010), built with the module they use, so no hash line ties them to it.
- **EVA-14** (deterministic) When `--archive` replaces a row whose `revision` was not empty with a new row whose `revision` is empty (the repository is gone or unreadable), the merged row must keep the archived `project` and `revision`.
- **EVA-15** (deterministic) Without a projects directory given, `session-metrics`, `rule-breaches`, `audit-sources`, `fixed-context` and `delivered-quality` must read the `projects/` directory of the configuration directory (`CLAUDE_CONFIG_DIR` when set and not empty, else the `.claude/` directory of the home directory, as AUD-2); when neither `CLAUDE_CONFIG_DIR` nor `HOME` is set and not empty, each must fail with a message naming both variables, except `delivered-quality`, whose transcript columns are then empty (QUA-7); when that default `projects/` cannot be read (missing, not a directory, not readable), each must print on stderr a warning naming it and the reason, then its usual output with no session (`delivered-quality` its empty transcript columns, QUA-7) and exit as with no transcript.
- **EVA-16** (deterministic) `main_context_peak` must be the largest, over the assistant messages of the session's own transcript that are not sidechain (counted once per `message.id` as EVA-2, sub-agents excluded, written in their own transcript or inline), of the sum of the `input_tokens`, `cache_read_input_tokens` and `cache_creation_input_tokens` of its `message.usage`, or, when its `message.usage.iterations` holds an entry of type `advisor_message` (an advised message, whose top-level usage adds up every executor iteration), the largest of that sum over its entries of type `message`: the size of the main context at its largest turn; 0 when the main transcript has no such message. A row archived before this rule kept the top-level sum, so the peak of an advised session archived then is overstated.
- **EVA-17** (deterministic) With `--archive`, an archive whose header is the one of EVA-1 without `main_context_peak` (written before that column) must be merged as if it had the current header, each of its rows given an empty `main_context_peak`.
- **EVA-18** (deterministic) `advisor_models` must list the distinct top-level `advisorModel` values of the assistant lines of the session, sub-agents included, joined by `,` in order of first appearance; empty when no line carries one.
- **EVA-19** (deterministic) `advisor_calls` must count the `server_tool_use` blocks named `advisor` of all the assistant lines of the session, sub-agents included (counted as `tool_calls` counts the `tool_use` blocks, EVA-2, and not in `tool_calls`); `advisor_input_tokens` the sum, over the entries of type `advisor_message` of the `message.usage.iterations` of each assistant message counted once per `message.id` (EVA-2), of their `input_tokens`, `cache_read_input_tokens` and `cache_creation_input_tokens`, and `advisor_output_tokens` that of their `output_tokens`; the three cells are empty when `advisor_models` is (no advisor was set, which is not 0 calls), 0 when an advisor was set and not called.
- **EVA-20** (deterministic) With `--archive`, an archive whose header is the one of EVA-1 without the four advisor columns (written before them), or the one of EVA-17, must be merged as if it had the current header, each of its rows given empty cells for the columns its header lacks.

## Scenarios

- (EVA-19) Given a Sonnet session whose `advisorModel` is Opus and whose one assistant message, split over three lines, holds a `server_tool_use` block named `advisor`, an `advisor_tool_result` block and usage iterations `message`, `advisor_message` (21,110 input and 479 output tokens), `message`, when the row is printed, then `advisor_calls` is 1, `advisor_input_tokens` 21110, `advisor_output_tokens` 479, `tool_calls` 0 and `input_tokens` holds none of the advisor's tokens.
- (EVA-19) Given a session with no `advisorModel`, when the row is printed, then the four advisor cells are empty.
- (EVA-2) Given an assistant message split over three lines with the same `message.id`, each carrying the same usage and one `tool_use`, when the row is printed, then `turns` is 1, the tokens are those of one usage and `tool_calls` is 3.
- (EVA-8) Given a project whose configuration moved from `rev = "a"` to `rev = "b"` in a commit at 10:00, when a session starts at 09:00, then its revision is `a`; at 11:00, `b`.
- (EVA-8) Given a session run in a linked worktree on a branch that changed the pin, when the revision is read, then it is the pin of the default branch, since the branch may be gone.
- (EVA-16) Given a main assistant message whose top-level usage reads 4 input, 28,546 cache read and 10,919 cache creation tokens and whose `message` iterations read (2, 9,012, 10,522) and (2, 19,534, 397), when the row is printed, then `main_context_peak` is 19,933 and `input_tokens` is 4.
- (EVA-16) Given a main transcript whose turns read 1,000 then 5,000 then (after a compaction) 2,000 tokens of input and cache, and a sub-agent turn of 9,000, when the row is printed, then `main_context_peak` is 5,000.
- (EVA-11) Given an archive holding sessions A and B, when the transcripts hold only B (changed) and C, then the archive holds A, the new B and C.
- (EVA-15) Given `CLAUDE_CONFIG_DIR` naming a directory whose `projects/` holds a session and `HOME` one whose `.claude/projects/` holds another, when `session-metrics` runs with no argument, then it prints the session of `CLAUDE_CONFIG_DIR` only.
- (EVA-15) Given `CLAUDE_CONFIG_DIR` naming a directory with no `projects/`, when `session-metrics` runs with no argument, then it prints its header only, warns on stderr naming that `projects/` and exits 0; the same when `projects` is a file.

## Non-goals

- Whether the advisor set was attached to the requests: an advisor less capable than the main model is not, yet its
  `advisorModel` is written; `advisor_models` records the setting, `advisor_calls` the calls that happened.
- The advice: its result block (`advisor_tool_result`, often `advisor_redacted_result`, encrypted) is never read
  (EVA-10).
- Judging a session (good, bad, rule broken): the detectors and the report are other issues.
- The price in money of the tokens: models and prices change; the tokens by kind are enough to price later.
- A complete list of the line types: an unknown type is counted, not an error.
- Counting the slash commands the user types (`<command-name>…`): the typed-message filter drops them, so they count in neither `validations` nor `other_messages`; measured at 0.3 % of the typed messages on 2026-10-26 (`issues/done/count_typed_slash_commands_as_interventions.md`), a `slash_commands` column by command name is the candidate if they become a usual way to steer the work.
