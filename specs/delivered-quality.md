# Quality signals of the delivered issues

## Intent

`cardinal run delivered-quality` measures what happened to the work of each done issue of a repository
after it was delivered (fixes, reverts) and while it was made (review findings, failed checks, typed messages), one
row of numbers per issue, so the evaluation report compares Cardinal revisions on quality and not only on cost. It
reports signals, not verdicts: a fix after a feature may come from a new need.

## Requirements

- **QUA-1** (deterministic) `delivered-quality [repo] [--projects <dir>] [--window-days <n>] [--summary]` must print a header line then one tab-separated row per file of `issues/done/` in the work tree of `repo` (default the current directory), sorted by `closed`, with the columns `issue`, `revision`, `closed`, `deliverables`, `commits`, `fixes_in_issue`, `fixes_after`, `reverts_after`, `reviews`, `review_findings`, `traced`, `traced_without_red`, `spec_lines`, `doc_lines`, `sessions`, `failed_checks`, `validations`, `other_messages`, `input_tokens`, `cache_read_tokens`, `output_tokens`; `issue` is the file stem. A `--window-days` that is not a whole number from 0 to 3650, or a `--projects` with no value, must be refused with an error and a non-zero exit.
- **QUA-2** (deterministic) The commits of an issue must be the non-merge commits of the default branch (as EVA-8 picks it) that touch `issues/<stem>.md` or `issues/done/<stem>.md`, from the oldest one whose version of that file holds a `# Tracking` heading outside a fenced code block (QUA-12) to the one that adds `issues/done/<stem>.md` (the close commit), both included, except the commits that add another `issues/done/*.md` file and not this one (they close another issue and only rewrite its citations); `commits` is their count and `closed` the author date of the close commit. An issue with no close commit on the default branch has no row.
- **QUA-3** (deterministic) `deliverables` must count the lines of the `## Plan` section of the done issue file (when it has none, of the `# Tracking` section before its first sub-heading, the layout of the older issues) that start with a number, `.`, a space and `[x]` or `[ ]`, a section ending at the next line starting with `#` outside a fenced code block (QUA-12); `fixes_in_issue` the commits of the issue whose subject has the type `fix` or `revert` (`AGENTS.md`).
- **QUA-4** (deterministic) The files of an issue must be the paths changed by its commits, except those under `issues/` or `docs/` and the lock (`.claude/cardinal.lock`, `.claude/harness.lock`); `fixes_after` must count the non-merge commits of the default branch that come after its close commit in the history and are authored at most `--window-days` days (default 30) after it, have the subject type `fix` and change at least one file of the issue; `reverts_after` counts the same way the commits whose subject has the type `revert` or starts with `Revert "`, or whose message cites `This reverts commit <hash>` of a commit of the issue.
- **QUA-5** (deterministic) `revision` must be the Cardinal revision in force one second before the author date of the oldest commit of the issue, as EVA-8 defines it (`transcripts.rs`): the Cardinal the work was done with, not the one the issue may itself change.
- **QUA-6** (deterministic) In the `# Tracking` section of the done issue file, each line holding `Code review` (case-insensitive) and not starting with `|` (a row of the `check | result` table) must count one in `reviews`, the section ending at the next line starting with `# ` outside a fenced code block (QUA-12) (its `##` sub-headings, such as `## Deliverable n`, stay in it); `review_findings` sums over them the number `<n>` of the first `<n> finding` or `<n> findings` of the line (0 for `no findings`; what follows may count the fixed ones), and is empty when a line holds neither, since the findings of that review are unknown.
- **QUA-7** (deterministic) The sessions of an issue must be, for each of its commits, the latest-starting session of the projects directory (`--projects`, default EVA-15) whose repository (EVA-7) is `repo` and whose span holds the commit's author date (as BRE-9), taken among the sessions whose branches (EVA-6) include the issue's stem when one does (an issue worktree, ADR 0003, while another session works in parallel); `sessions` is their distinct count. The transcript columns (`sessions`, those of QUA-8 and of QUA-15) must be empty, not 0, when the projects directory cannot be read.
- **QUA-8** (deterministic) In a session of the issue, an event counts for the issue when its timestamp lies at or before the latest author date of the issue's commits in that session, and after the latest author date, in that session's span, of a commit of the default branch that is not a commit of the issue and comes before the earliest of them (else at or after the session start; always from the session start when the session's branches include the issue's stem); `failed_checks` counts the `Bash` calls whose command holds `just` followed by a word starting with `check` or `test` and whose result is an error, and `validations` and `other_messages` the typed messages split as EVA-4.
- **QUA-9** (deterministic) With `--summary`, the script must print instead a header then one row per `revision`, with the column `issues` (their count) followed by the sums of the numeric columns of QUA-1 over its issues, sorted by the earliest author date of the oldest commits of its issues (the order the revisions were used in); a sum over an empty value is empty, except for the three token columns of QUA-15, summed over the issues whose cells are not empty (0 when none is) and followed by the last column, `token_issues`, the count of those issues.
- **QUA-10** (deterministic) The output must hold no text of a message, of a commit or of an issue: only stems, revisions, dates and counts.
- **QUA-11** (deterministic) `traced` must count the distinct requirement ids (`ABC-n`, as `check-specs` reads them) cited on the citation lines (QUA-13) that the commits of the issue add to its files (QUA-4), renames detected, less, commit by commit, the ids cited on the citation lines that commit removes (a moved or extended citation traces only its new ids); `traced_without_red` counts those of them absent from the id list that opens each `red:` item of the `# Tracking` section (ending at the next line starting with `# ` outside a fenced code block, QUA-12), an item being a line whose trimmed text, list marker removed, starts with `red:`, with its indented continuation lines, and its list the ids that follow `red:`, separated by commas or spaces, up to the first other word; both are empty when the diffs of the issue cannot be read.
- **QUA-12** (deterministic) The sections of an issue file that QUA-3, QUA-6 and QUA-11 read must start at the first line equal to their heading (trailing spaces ignored) outside a fenced code block and end as each requirement says, a line inside a fenced code block never starting or ending one; a fenced code block opens at a line whose text, leading whitespace removed, starts with at least three backticks (the rest of the line holding no backtick, else it is inline code) or three tildes, and closes at the next line whose text, leading and trailing whitespace removed, is only the same character, at least as many times; a block left open runs to the end of the file. A section whose heading the file holds only inside a fenced code block is unread: the columns read from it (`deliverables` when neither of its headings stands outside a fence, `reviews` and `review_findings`, `traced_without_red`) must be empty, not 0; a heading the file does not hold at all reads as an empty section.
- **QUA-13** (deterministic) The citation lines of QUA-11 must be those `check-specs` reads: in the files whose name matches the test-file patterns (TRC-11, at the revision the report runs on), the lines it reads as citations for their extension (TRC-12), so that a `# spec:` line of a `.py` test file counts and one of a `.rs` file or of a non-test file does not.
- **QUA-14** (deterministic) `spec_lines` must sum, over the commits of the issue, the added and removed lines (as `git diff --numstat` counts them against the commit's first parent, renames detected) of the `.md` files under `specs/` other than `specs/README.md` and `specs/TEMPLATE.md`; `doc_lines` the same of the doc files: the `.md` files under `docs/` outside `docs/adr/`, the files the `root_docs` of `.claude/cardinal.toml` lists (`README.md` when it lists none or cannot be read) and the file its `architecture` names, all read at the revision the report runs on, less the files its `roadmap` lists. A binary file counts 0; both are empty when the diffs of the issue cannot be read.
- **QUA-15** (deterministic) An assistant message of a session of the issue, sub-agents included (EVA-3), counted once per `message.id` over the sessions of the issue (EVA-2; a resumed session repeats the messages of the one it resumes) at the timestamp of its first line, is an event of QUA-8; `input_tokens` must sum over these messages the `input_tokens`, `cache_read_input_tokens` and `cache_creation_input_tokens` of their `message.usage` (the input sum of REP-5), `cache_read_tokens` their `cache_read_input_tokens` and `output_tokens` their `output_tokens`, the top-level usage only: that of an advised message already adds up its executor iterations and holds none of the advisor's tokens (EVA-19); the three cells are empty, not 0, when the issue has no session (`sessions` 0: its transcripts are gone or its commits were made outside a session).
- **QUA-16** (deterministic) The rows must give, right after `revision`, `setup`: the setup (REP-15) of each session of the issue (QUA-7), read from its transcript (the first `message.model` of its assistant lines and the first `advisorModel` of its lines, sub-agents included, in order of first appearance as EVA-6 and EVA-18 read them), when they are all the same, `mixed` when they differ, and empty when the issue has no session with a model or the projects directory cannot be read.
- **QUA-17** (deterministic) With `--summary`, the rows must be one per `revision` and `setup` (QUA-16) of the issues, the column `setup` right after `revision`, sorted as QUA-9 sorts the revisions, then by setup name (the empty one first); each row sums the issues of its pair only.

## Scenarios

- (QUA-2) Given an issue opened in a `docs` commit, then three commits of its deliverables, then another issue closed by a commit that rewrites a citation in its file, then its own close commit, when the row is printed, then `commits` is 4.
- (QUA-4) Given an issue closed on day 0 that changed `src/a.rs`, when a `fix` commit changes `src/a.rs` on day 10 and another on day 40, then `fixes_after` is 1 with the default window.
- (QUA-4) Given a later `fix` commit that only changes `docs/architecture.md` and `.claude/cardinal.lock`, when the row is printed, then it is not in `fixes_after`.
- (QUA-5) Given an issue whose first commit changes the pinned revision from `r1` to `r2`, when the row is printed, then its revision is `r1`.
- (QUA-11) Given an issue whose commits add `// spec: ABC-1, ABC-2` and `// spec: ABC-3` to a test and whose tracking holds `red: ABC-1, ABC-3: assertion failed`, when the row is printed, then `traced` is 3 and `traced_without_red` 1.
- (QUA-11) Given an issue whose commit only renames a test file that cites `// spec: ABC-1`, when the row is printed, then `traced` is 0.
- (QUA-11) Given an issue whose commit turns `// spec: ABC-1` into `// spec: ABC-1, ABC-5` and whose tracking holds `- red: none (ABC-5 not covered: ABC-6)` and `Not covered: ABC-5`, when the row is printed, then `traced` is 1 and `traced_without_red` 1.
- (QUA-11) Given an issue whose commit adds `// spec: ABC-1 (internal: the ABC-2 fixture is slow)` to a test, when the
  row is printed, then `traced` is 1.
- (QUA-7) Given a session on the branch `alpha` and a later-starting session on another branch both holding a commit of the issue `alpha`, when the row is printed, then the commit counts with the first.
- (QUA-6) Given an issue file with `Code review: 6 findings` and `Code review: no findings`, then `reviews` is 2 and `review_findings` 6; with one more `Code review: fixed the doc`, `review_findings` is empty.
- (QUA-2) Given an issue opened in a commit whose Goal quotes `# Tracking` in a fence, then a commit adding its `# Tracking` section, a commit of its deliverable and its close commit, when the row is printed, then `commits` is 3.
- (QUA-12) Given an issue file whose fence opened in the Goal is left open before its `# Tracking` section, when the row is printed, then `deliverables`, `reviews`, `review_findings` and `traced_without_red` are empty; given an issue file with no `# Tracking` nor `## Plan` heading, then `deliverables` and `reviews` are 0.
- (QUA-12) Given an issue file whose Goal quotes `# Tracking` in a backtick fence and whose `# Tracking` holds, in an indented `~~~` fence, a line `# build` followed by `Code review: 2 findings` after the fence, when the row is printed, then `reviews` is 1 and `review_findings` 2.
- (QUA-13) Given an issue whose commits add `# spec: ABC-1` to `tests/test_a.py` and `# spec: ABC-2` inside a string
  of `src/lib.rs`, with `spec_files = ["*.rs", "test_*.py"]`, when the row is printed, then `traced` is 1; a `# spec:
  ABC-3` added to `ci.yml` or `scripts/gen.py` does not count.
- (QUA-14) Given an issue whose commits add 40 lines to `specs/a.md`, 3 to `specs/README.md`, change 5 lines of `docs/guide.md` (5 added, 5 removed), add 20 to `docs/adr/0001-x.md`, 2 to `README.md` and 7 to `CLAUDE.md`, with no `.claude/cardinal.toml`, when the row is printed, then `spec_lines` is 40 and `doc_lines` 12.
- (QUA-14) Given `root_docs = ["GUIDE"]`, `architecture = "design/arch.md"` and `roadmap = ["docs/TODO.md"]`, when an issue adds 3 lines to each of `GUIDE`, `design/arch.md`, `docs/TODO.md` and `README.md`, then `doc_lines` is 6.
- (QUA-14) Given an issue whose commit only renames `docs/a.md` to `docs/b.md`, when the row is printed, then `doc_lines` is 0.
- (QUA-15) Given an issue whose one session holds an assistant message split over two lines with the same `message.id` and a usage of 10 input, 1,000 cache read, 200 cache creation and 50 output tokens, a sub-agent message of 5 input and 7 output tokens, and a message after the issue's last commit, when the row is printed, then `input_tokens` is 1215, `cache_read_tokens` 1000 and `output_tokens` 57.
- (QUA-9) Given a revision of two issues, one whose session spent 1,000 input tokens and one closed outside any session, when the summary is printed, then its `input_tokens` is 1000 and its `token_issues` 1.
- (QUA-16) Given an issue made in two sessions of `claude-sonnet-5-5` with an Opus advisor set, then a third of `claude-opus-5-5` with none, when the row is printed, then its `setup` is `mixed`.

## Non-goals

- Judging an issue: a fix after a feature may come from a new need; the report reads the trend.
- The issues closed before the `issues/done/` convention or in another repository than the one given: run the script once per repository.
- The commits not yet on the default branch (as EVA-8 picks it, `origin/HEAD` first): an issue closed locally and not pushed has no row yet.
- Archiving the rows: the git columns can be recomputed at any time; the transcript columns follow the retention of the transcripts.
- The tokens of an issue that never reaches `issues/done/` (abandoned, or not closed yet), and those of a session that made no commit of the issue (a plan stopped before its first deliverable, a session that only answered questions): QUA-7 finds the sessions through the commits.
- The advisor's tokens: `cardinal-report` gives them per session (REP-11).
