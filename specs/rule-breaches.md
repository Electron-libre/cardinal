# Breaches of the Cardinal rules in the session transcripts

## Intent

`cardinal run rule-breaches` reads the Claude Code transcripts of every project and lists where the agent
broke a rule Cardinal states (`AGENTS.md`, the skills, the ADRs), apart from where a gate refused it, then counts
them per rule and per Cardinal revision over the sessions where the rule applied, so `audit-instructions` can tell a
rule broken often (a hook candidate) from a rule that rarely applies. Only the breaches a program can see are in
scope. It also lists the known patterns of token waste a program can see, so a change of the instructions or of a
tool gets a verdict on the waste it removes.

## Requirements

- **BRE-1** (deterministic) `rule-breaches [projects_dir]` must print a header line then one tab-separated row per finding, with the columns `session`, `project`, `revision`, `rule`, `kind`, `location`, `detail`; `kind` is `breach` when the act went through and `blocked` when a hook or a permission rule refused it; `location` is `<transcript file name>:<line>` (1-based, the file name of a sub-agent transcript being `subagents/<name>`), empty for a finding read from git.
- **BRE-2** (deterministic) `project` and `revision` must be resolved as in `session-metrics` (EVA-7, EVA-8), through the shared module `transcripts.rs`, so both scripts give a session the same project and revision; no rule applies to a session whose `revision` is empty (the project had no Cardinal then).
- **BRE-3** (deterministic) With `--summary`, the script must print instead a header then one row per rule and revision, with the columns `rule`, `revision`, `applied` (sessions where the rule applied, as each requirement below defines), `breached` (those with at least one `breach`), `breaches` and `blocked` (counts of findings), sorted by rule then revision.
- **BRE-4** (deterministic) Rule `no-verify`: a `Bash` call whose command holds the words `git` and `commit` or `push` and the token `--no-verify` must be a finding (`blocked` when its result is an error). It applies to the sessions with a `Bash` call holding `git` and `commit` or `push`.
- **BRE-5** (deterministic) Rule `review-before-commit`: an error result of a `Bash` call holding `git` and `commit` whose text holds `Refused:` and `code review` but not `Refused: only the user waives` must be a `blocked` finding (a refusal of another command is a mistake of the gate, not of the agent); a `Bash` call holding `git` and `commit` whose result is not an error, after such a refusal with neither a `Skill` call whose skill name ends with `code-review` nor a user turn in between (a typed message, the filter of `transcripts.rs`, or a command the user typed: a user line, not meta nor sidechain, whose text holds `<command-name>/` or starts with `<bash-input>`), must be a `breach` (the bypass of ADR 0005). It applies to the sessions with a `Bash` call holding `git` and `commit`.
- **BRE-6** (deterministic) Rule `review-waiver`: a `Bash` call whose command runs the recipe `waive-review` (the words `just` and `waive-review`), an `Edit` or `Write` of a path whose file name is `claude-review-waived`, or an error tool result holding `Refused: only the user waives` must be a finding (`blocked` when the result is an error). It applies to the sessions with a `Bash` call holding `git` and `commit`.
- **BRE-7** (deterministic) Rule `managed-copy`: an `Edit`, `Write` or `NotebookEdit` call whose `file_path`, made relative to the work tree of the `cwd` of its line, is listed in the `.claude/cardinal.lock` (else `.claude/harness.lock`, for a commit before the rename of ADR 0015) committed on the default branch of the project at the session's `start` must be a finding with that relative path as `detail` (`blocked` when its result is an error). It applies to the sessions with at least one such call in a project whose lock could be read.
- **BRE-8** (deterministic) Rule `validation-stop`: once an `Edit` or `Write` call of the session's own transcript puts the text `Plan: proposed` in a file under `issues/`, each `Edit`, `Write` or `NotebookEdit` call before the next user turn (BRE-5) whose path lies in the work tree of its line but not under `issues/`, `specs/` or `docs/adr/` must be a `breach` with that path as `detail`. It applies to the sessions that wrote `Plan: proposed`.
- **BRE-9** (deterministic) Rules `commit-attribution` and `commit-format`: each non-merge commit of the local branches of the project's repository whose author date lies between the `start` and the end of a session of that project must be checked once, against the latest-starting such session (a commit in no session was the user's and is skipped); a message with a line holding `co-authored-by:`, `noreply@anthropic.com`, or `generated with` and `claude` (case-insensitive) is a `commit-attribution` breach, and a subject that is not `<type>(<scope>): <description>` or `<type>: <description>` with a type of `AGENTS.md`, a scope among `docs`, `cardinal`, `harness` (its name before the rename, still read in the past commits) and the `commit_scopes` of the `.claude/cardinal.toml` (else `.claude/harness.toml`, for a commit before the rename of ADR 0015) of that commit, at most 72 characters, a description not starting with a capital letter nor ending with `.` is a `commit-format` breach; `detail` is the abbreviated hash. Both apply to the sessions with at least one checked commit.
- **BRE-10** (deterministic) Rule `user-language`: when the session's `user_language` (BRE-14) is `French` or `English` (in any case, blanks around it ignored), each assistant text block of the session's own transcript that holds at least 20 words once inline code and fenced code blocks (read with the fence rule of QUA-12, `specs/delivered-quality.md`) are removed, and holds more stop words of the other language than of that one (from the two lists of the script), must be a `breach`. It applies to the sessions with at least one such block.
- **BRE-11** (deterministic) The output must hold no text of a message, of a tool input or of a tool result: only identifiers, rule names, counts, paths and commit hashes.
- **BRE-12** (deterministic) withdrawn: as EVA-13, no hash line since the readers are modules of `harness`.
- **BRE-13** (deterministic) The `detail` of a `user-language` breach must be `hinted` when a hint of the `language-hint` hook (an `attachment` line of type `hook_additional_context`, or a meta user line starting with `Stop hook feedback:`, holding `the user_language of .claude/cardinal.toml`) comes after its run of text blocks (the blocks with no tool call between them) and before the next run or user turn (BRE-5), else `final` when no assistant text block comes after it before the next user turn, else `intermediate`.
- **BRE-14** (deterministic) The `user_language` of a session must be the string `user_language` of the `[project]` table of the personal configuration `.claude/cardinal.local.toml` at the root of the session's repository as it is when the measure runs, when that file is valid TOML and holds one, else that of the `.claude/cardinal.toml` (else `.claude/harness.toml`, for a commit before the rename of ADR 0015) committed at the session's `start`.
- **BRE-15** (deterministic) Rules `skill-routing-<skill>` (BRE-16 to BRE-18): a `<skill>` is loaded at a line of the session's own transcript when an earlier line of it holds a `Skill` call whose skill is `<skill>` or `<prefix>:<skill>` and whose result is not an error, or a command the user typed (BRE-5) holding `<command-name>/<skill><` or `<command-name>/<prefix>:<skill><`; each trigger of the rule in the session's own transcript at which its skill is not loaded must be a finding at the trigger's call (`blocked` when its result is an error). A rule applies to the sessions whose own transcript holds its trigger and whose lock committed at the session's `start` (BRE-7) lists `.claude/skills/<skill>/SKILL.md`.
- **BRE-16** (deterministic) Rule `skill-routing-commit-message`: its trigger must be a `Bash` call with a word `git` whose subcommand, the first word after it that is not an option (`-C` and `-c` taking the next word), is `commit`, with no `--no-edit` before the next word `git`.
- **BRE-17** (deterministic) Rule `skill-routing-issue-workflow`: its trigger must be an `Edit` or `Write` call that puts a line `Plan: proposed` (blanks around it ignored) in a file under `issues/`: a sentence that quotes the marker proposes no plan.
- **BRE-18** (deterministic) Rule `skill-routing-write-spec`: its trigger must be a `Write` call whose path, relative to the work tree of its line (BRE-7), lies under `specs/`, ends with `.md`, is not `specs/README.md`, was not committed on the default branch at the session's `start` and no earlier call of the session wrote, with that relative path as `detail`.
- **BRE-19** (deterministic) Rule `oversized-result`: a tool result of a transcript (the session's own or a sub-agent's) whose text (its string content, else the `text` of its parts joined by newlines) holds more than 25,000 bytes must be a `breach` located at its line, with `detail` that number of bytes. It applies to the sessions with at least one tool result.

## Scenarios

- (BRE-5) Given a refused commit, then a `/code-review` call, then a commit that passes, when the session is read, then there is one `blocked` finding and no `breach`.
- (BRE-5) Given a refused commit, then a commit that passes with nothing in between, when the session is read, then there is one `blocked` finding and one `breach`.
- (BRE-4) Given the command `echo "a << b"` then, on the next line, a commit with `--no-verify`, when the session is read, then the flag is found: a `<<` inside quotes starts no here-document.
- (BRE-9) Given a commit the user wrote before the session and the agent rebased during it, when the commits are read, then it is skipped: its author date lies outside the session; a stash or a note is on no local branch.
- (BRE-8) Given a session that writes `Plan: proposed` in an issue, then edits `src/main.rs`, then reads a typed `ok`, then edits `src/lib.rs`, when the session is read, then only `src/main.rs` is a breach.
- (BRE-10) Given `user_language = "french"` and a block of 25 English words, when the session is read, then the block is a breach; given a French block of 25 words holding `un an` and `tu as`, it is not: neither `an` nor `as` is an English stop word.
- (BRE-13) Given an English block followed by the hint of the `PostToolUse` hook (withdrawn by LNG-7 of `specs/language-hint.md`: only transcripts of before carry it, so from that revision on a block between calls is `intermediate`) then a French block before the next typed message, when the session is read, then the English block is a breach with `detail` `hinted`; without the hint it is `intermediate`, and the last block before a typed message is `final`.
- (BRE-13) Given an English block hinted after its call, then English blocks before two later calls, then an English last reply sent back by the Stop hook, when the session is read, then the first block and the last reply are `hinted` and the two others `intermediate`: each hint covers the run it judged.
- (BRE-14) Given `user_language = "French"` committed at the session's `start` and `user_language = "English"` in the personal `.claude/cardinal.local.toml` of the repository, when a session of 25-word English blocks is read, then it has no `user-language` breach; with `user_language = "German"` in the personal file, the rule does not apply to it.
- (BRE-3) Given a rule that applied in ten sessions of a revision and was broken in one, when the summary is printed, then its row reads `applied` 10 and `breached` 1.
- (BRE-15) Given a commit, then a `Skill` call of `commit-message`, then a second commit, when the session is read, then only the first commit is a `skill-routing-commit-message` finding; given the user's `/commit-message` command before both, neither is.
- (BRE-15) Given a commit in a session whose lock lists no `.claude/skills/commit-message/SKILL.md`, when the session is read, then `skill-routing-commit-message` does not apply to it.
- (BRE-18) Given a `Write` of `specs/new.md` and one of `specs/old.md`, committed before the session, when the session is read with no `write-spec` call, then only `specs/new.md` is a finding.
- (BRE-19) Given a result of exactly the threshold and one a byte over it, when the session is read, then only the second is a breach.

## Non-goals

- The rules that need judgment (the shape of the reports to the user): a later LLM judge.
- One worktree per issue (ADR 0003): it is required only for agents working in parallel, which one transcript cannot show.
- The `files:<skill>` calls of the Cardinal repository: Claude Code offers the skills under `files/` as directory-scoped skills and tells the agent to prefer them there; they are the same text as the synced copies, so calling them is no breach.
- A write made through `Bash` (a heredoc, `sed -i`): only the `Edit`, `Write` and `NotebookEdit` calls are read for the file rules.
- A command that breaks a rule only by a construction nobody would write by mistake (ADR 0005), such as `-n` for `--no-verify` or a shell variable holding the flag.
- A skill skipped for a good reason (the user commits by hand, asks for a quick fix): the `skill-routing-<skill>` rules are a signal, never a gate; a commit or a spec the user writes is no call of the agent and no trigger.
- A skill loaded in a sub-agent, or a trigger in a sub-agent's transcript: the sub-agent does not share the session's context.
- A file read again unchanged (no `Bash` call, no edit of it and no compaction in between), a repeated call (same tool, same input) and a retry loop (failing calls in a row with the same error): measured on the local transcripts before this rule, a file read again unchanged occurred in no transcript of 1611, a repeated read-only call other than `Read` was rare and a `Bash` call is repeated after the state it reads changed, which a transcript cannot show; three identical failures in a row occurred in 2 transcripts of 1611.
- Whether the agent used a large result: it takes judgment; `oversized-result` counts its size only, and the bytes of `detail` are the only estimate of the tokens a finding wastes.
