# Report of the Cardinal evolution by revision

## Intent

`cardinal run cardinal-report` joins the outputs of the transcript readers (`session-metrics`,
`rule-breaches --summary`, `delivered-quality --summary`, `fixed-context`) into one markdown table per axis
(efficiency, quality, rules, skills, fixed context), one row per group of consecutive Cardinal revisions, with the
confounders and the sample size next to the numbers, so `skill:evaluate-harness` shows the trend without computing
it. It reports trends, never a pass or a fail.

## Requirements

- **REP-1** (deterministic) `fixed-context [projects_dir]` must print a header line then one tab-separated row per project (EVA-7) of the sessions of `projects_dir` (default EVA-15) and Cardinal revision (EVA-8) used by one of them, with the columns `project`, `revision`, `commit`, `claude_md_bytes`, `agents_md_bytes`, `skill_description_bytes`, `skills`, sorted by project then by the earliest start of the revision's sessions; the revision `` (empty) has no row.
- **REP-2** (deterministic) The `commit` of a row must be the abbreviated hash of the oldest commit of the first-parent history of the project's default branch at which the revision is in force (EVA-8, for a `self:` revision its own commit), and the byte columns must be read from the tree of that commit: `claude_md_bytes` the sizes of the memory files a session of the project loads at launch, `AGENTS.md` and `.claude/AGENTS.md` excepted, and `agents_md_bytes` the sizes of these two when loaded, and the sum over the `.claude/skills/*/SKILL.md` files of the bytes of their top-level front matter `name` and `description` values (quotes removed, a value over several lines, blank lines included, counted with one byte per line break); `skills` lists the skill directory names joined by `,`, sorted. The memory files loaded at launch are `CLAUDE.md`, `.claude/CLAUDE.md`, the `.claude/rules/**/*.md` files whose front matter has no `paths` key, `AGENTS.md` and `.claude/AGENTS.md` in place of the first two when neither exists, and the files these import, each file counted once however many paths name it: an import is a `@<path>` at the start of a line or after a white space, outside a Markdown code span and a fenced code block, its path ending at the first white space a backslash does not escape; a relative path resolves against the directory of the importing file, a symbolic link followed, imports are followed up to four hops, and a path that is absolute, starts with `~` or leaves the repository counts nothing. A file counts its bytes as they are (0 when absent; a symbolic link counted as the file it points to in the same tree). A revision with no such commit (pinned on another branch, history unreadable) has its columns after `revision` empty.
- **REP-3** (deterministic) `cardinal-report --sessions <file> [--breaches <file>] [--quality <file>]... [--context <file>] [--changes <file>] [--min-sessions <n>] [--min-issues <n>] [--anonymous]` must read the rows of `session-metrics` (EVA-1), the summary of `rule-breaches` (BRE-3), one or more summaries of `delivered-quality` (QUA-9) and the rows of `fixed-context` (REP-1) and of `cardinal-changes` (VRD-3), and print one markdown table per axis (the verdicts of VRD-5 apart), each under a `## <Axis>` heading, whose first two columns are `group` and `sessions`. A file whose header is not the expected one, a missing `--sessions`, an unknown option, a `--min-sessions` that is not a whole number from 1 to 1000 (default 10), or a `--min-issues` that is not one (default 5, VRD-11, VRD-12) must be refused with an error and a non-zero exit.
- **REP-4** (deterministic) The revisions must be ordered by the earliest `start` of their sessions (the order they were used in; the empty revision, and a revision with no session, are left out of every table) and cut into groups of consecutive revisions, each closed as soon as it holds at least `--min-sessions` sessions; a group is named `<first revision>` or `<first revision>..<last revision>`, a revision of 40 hexadecimal digits (after `self:` or not) written with its first 7, and the last group, when it holds fewer sessions, shows in every table one row with its `sessions` and `too few` in each other cell.
- **REP-5** (deterministic) The efficiency table (`## Efficiency`) must give per group `sessions`, `issues` (distinct pairs of project and issue of EVA-6), `projects`, `models` and `versions` (each `name=n`, `n` the sessions of the group that used it, most frequent first, then by name; `projects` is only the count of distinct projects with `--anonymous`), then the median per session (the mean of the two middle values for an even count, rounded half up to the unit) of `turns`, `tool_calls`, `output_tokens`, the sum of `input_tokens`, `cache_read_tokens` and `cache_creation_tokens` (column `input_tokens`), `main_context_peak` (REP-9) and its `peak_sessions` (REP-10), the advisor columns (REP-11), `validations` and `other_messages`.
- **REP-6** (deterministic) With `--quality`, the quality table (`## Quality`) must give per group the sums over its revisions and over the files given of the columns of the `delivered-quality` summary after `revision` (its `sessions` named `issue_sessions`; an empty value, or no row of its revisions, making its sum empty, as QUA-9), then `fixes_after_per_issue`, `findings_per_review` and `doc_lines_per_spec_line`, the ratios of `fixes_after` to `issues`, of `review_findings` to `reviews` and of `doc_lines` to `spec_lines` with two decimals, then `input_tokens_per_issue` and `output_tokens_per_issue`, the ratios of `input_tokens` and of `output_tokens` (QUA-15) to `token_issues` (QUA-9), the issues whose tokens are known, rounded half up to the unit (each ratio empty when a term is empty or the divisor 0). With `--breaches`, the rules table (`## Rules`) must give one row per group and rule of its revisions, sorted by rule (one row of empty cells for a group with none), with `rule`, the sums of `applied`, `breached`, `breaches`, `blocked`, and `breached_share`, `breached` over `applied` as a whole percent rounded half up (`17%`). A table whose input is not given is not printed.
- **REP-7** (deterministic) The skills table (`## Skills`) must give per group `calls` and `hook_refusals`, the `skills` and `hook_refusals` pairs of EVA-5 summed over its sessions (`name=n`, most frequent first, then by name), and, with `--context`, `unused`: the skills listed by the `fixed-context` rows of its revisions that no session of the group called (a call named `<skill>` or `<prefix>:<skill>` uses it), sorted and joined by `, `. With `--context`, the fixed context table (`## Fixed context`) must give per group the mean over the rows of its revisions whose byte columns are not empty of `claude_md_bytes`, `agents_md_bytes`, `skill_description_bytes` and their sum `total_bytes`, rounded half up to the unit (empty with no such row).
- **REP-8** (deterministic) The output must hold no text of a message, of a commit or of an issue, and with `--anonymous` no project name nor issue stem either (only revisions, model and version names, skill and hook names, counts and ratios).
- **REP-9** (deterministic) The efficiency table must give, after `cache_read_share` (REP-12), `main_context_peak`: the median (as REP-5) of the `main_context_peak` (EVA-16) of the group's sessions whose cell is not empty, empty when none is (an archived session read before the column, EVA-17, is left out rather than counted as 0).
- **REP-10** (deterministic) The efficiency table must give, right after `main_context_peak`, `peak_sessions`: the count of the group's sessions whose `main_context_peak` cell is not empty, the sample its median is computed from (0 when none is).
- **REP-11** (deterministic) The efficiency table must give, right after `peak_sessions`, `advisor_models` (as `models`, from the `advisor_models` of EVA-18), `advisor_sessions` (the count of the group's sessions whose `advisor_calls` cell is not empty, 0 when none is), then `advisor_calls`, `advisor_input_tokens` and `advisor_output_tokens` (EVA-19): each the median (as REP-5) over those sessions, empty when there is none.
- **REP-12** (deterministic) The efficiency table must give, right after `input_tokens`, `cache_read_share`: the median (as REP-5, on the shares before rounding) of the share of each session of the group whose input sum of REP-5 is not 0, that session's `cache_read_tokens` over that sum (the median of the ratios, not the ratio of the medians), written as a whole percent rounded half up (`33%`), empty when no session of the group has input.
- **REP-13** (deterministic) The rules table (REP-6) must give, after `breached_share`, `bytes`: the sum of the `bytes` (BRE-20) of the rule's rows in the group, empty when one of them is empty; then `bytes_per_session`: that sum over the rule's `applied`, rounded half up to the unit, empty when `bytes` is empty or `applied` is 0 (a mean over the sessions where the rule applied, not a median: most sessions waste nothing, so a median stays at 0).
- **REP-14** (deterministic) `cardinal-report` must accept `--by revision` (the default: the groups of REP-4) or `--by setup`, and refuse any other value, or none, with an error and a non-zero exit. With `--by setup`, the groups are the setups (REP-15) of the sessions of a non-empty revision instead, one group per setup named after it, ordered by their count of sessions, most first, then by name; a group of fewer than `--min-sessions` sessions shows in every table one row with its `sessions` and `too few` in each other cell, as REP-4.
- **REP-15** (deterministic) The setup of a session must be the first model of its `models` (EVA-6, the model of its first assistant message) followed by ` solo` when its `advisor_models` (EVA-18) is empty or starts with that model (a model never advises itself), else by ` advised by ` and the first model of its `advisor_models`; a session whose `models` is empty has no setup and is left out of every table under `--by setup`.
- **REP-16** (deterministic) With `--by setup`, the efficiency table must give, right after `versions`, `revisions`: the revisions of the group's sessions as `models` gives the models (`name=n`, written as REP-4 names them); the quality table sums the rows of the quality summaries whose `setup` (QUA-17) is the group's name, its columns unchanged; the skills table leaves out `unused`; and the rules table, the fixed context table and the verdicts, whose inputs are kept per revision, are not printed (their files still read and checked as REP-3 says).

## Scenarios

- (REP-4) Given revisions `a` (6 sessions), `b` (5) and `c` (3) used in that order with the default threshold, when the report is printed, then the groups are `a..b` (11 sessions) and `c`, marked `too few` with 3 sessions.
- (REP-4) Given a consumer pinned to an old revision used after newer `self:` revisions, when the report is printed, then the old revision takes its place by first use and the project mix of its group shows it.
- (REP-2) Given a `CLAUDE.md` of 100 bytes that names `AGENTS.md` in backticks and imports `@docs/rules.md` (50 bytes), when the row is printed, then `claude_md_bytes` is 150 and `agents_md_bytes` 0: Claude Code reads `AGENTS.md` only when imported or when there is no `CLAUDE.md`.
- (REP-2) Given a `CLAUDE.md` that is a symbolic link to `docs/main.md`, which imports `@inc.md`, when the row is printed, then it counts `docs/inc.md`, not `inc.md`: Claude Code resolves the import against the directory of the file the link points to.
- (REP-2) Given a project whose configuration moved from `r1` to `r2` in a commit that also grows `AGENTS.md`, when the row of `r2` is printed, then `agents_md_bytes` is the size in that commit.
- (REP-10) Given a group of 12 sessions, 9 of them archived before `main_context_peak`, when the report is printed, then `peak_sessions` is 3 and `main_context_peak` the median of those 3.
- (REP-6) Given a rule that applied in 8 sessions of `a` and 4 of `b`, broken in 1 of each, when `a..b` is a group, then its row reads `applied` 12, `breached` 2.
- (REP-6) Given a group whose quality rows sum `spec_lines` 200 and `doc_lines` 50, then its `doc_lines_per_spec_line` is `0.25`; with `spec_lines` 0, it is empty.
- (REP-6) Given a group whose quality rows sum 5 `issues`, 4 `token_issues`, `input_tokens` 3,000,002 and `output_tokens` 10,002, then its `input_tokens_per_issue` is `750001` and `output_tokens_per_issue` `2501`; with one row whose `input_tokens` is empty, its `input_tokens` sum and `input_tokens_per_issue` are empty.
- (REP-12) Given a group of 3 sessions with input sums of 10, 100 and 1,000 tokens, of which 9, 10 and 500 were cache reads, when the report is printed, then `cache_read_share` is `50%`: the median of 90%, 10% and 50%, whatever the sizes of the sessions.

- (REP-13) Given an `oversized-result` that applied in 3 sessions of `a` with `bytes` 70000 and 2 of `b` with `bytes` 30001, when `a..b` is a group, then its row reads `bytes` 100001 and `bytes_per_session` 20000.
- (REP-11) Given a group of 10 sessions, 4 with an Opus advisor set that called it 0, 1, 3 and 6 times, when the report is printed, then `advisor_models` is `claude-opus-5-5=4`, `advisor_sessions` 4 and `advisor_calls` 2.
- (REP-14) Given 12 sessions of `claude-sonnet-5-5 advised by claude-opus-5-5`, 15 of `claude-opus-5-5 solo` and 4 of `claude-sonnet-5-5 solo` with the default threshold, when the report is printed with `--by setup`, then the groups are `claude-opus-5-5 solo` (15), `claude-sonnet-5-5 advised by claude-opus-5-5` (12) and `claude-sonnet-5-5 solo`, marked `too few` with 4 sessions.
- (REP-15) Given a session whose `models` is `claude-sonnet-5-5,claude-haiku-5-5` (an Explore sub-agent) and whose `advisor_models` is `claude-opus-5-5`, then its setup is `claude-sonnet-5-5 advised by claude-opus-5-5`; with `models` `claude-opus-5-5` and the same `advisor_models`, it is `claude-opus-5-5 solo`.

## Non-goals

- A verdict or a threshold on the agent's behaviour: numbers become targets once shown; the report gives trends.
- Causes: model, Claude Code version and project change with the revision; the report shows them, a targeted
  revert of the suspected change confirms a trend.
- The false positives of the hook refusals and the skills called where another fits: they need judgment.
- The text a hook prints in a session: the shared hooks print only on a refusal, already counted.
- Memory a session loads from outside the repository (`~/.claude/CLAUDE.md`, a `CLAUDE.md` of a parent directory, an import
  outside the repository), on demand (a subdirectory's `CLAUDE.md`, a rule with `paths`), or through a user setting
  (`claude-md-and-agents-md`); the HTML comments Claude Code strips are counted: the measure is of the project's files.
- A controlled comparison of the setups: a setup is the user's choice, often per task difficulty, so `--by setup`
  is observational; the reference task set replays the same tasks under each.
- Archiving the report: the session rows have their archive (EVA-11) and the git signals can be recomputed.
